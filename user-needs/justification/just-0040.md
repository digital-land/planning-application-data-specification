The `additional-information-requested` and `additional-information-received` values record both types of event. Together with `event-date` and `planning-application`, they support analysis of how requests for additional information contribute to delays.

The need is only partially satisfied because the timeline does not link a received-information event to the request it answers. Where an application has more than one request, users cannot reliably calculate how long each request took to resolve. This limits both service-level monitoring and comparison across applications and planning authorities.
